SECTION 1 — LOGIN & AUTHENTICATION
================================================================================

PURPOSE
  Sign in to the ROW application using your organisation email and password.

STEPS
  1. Open the ROW application in your browser or PWA.
  2. You will be taken to the Login page automatically if you are not signed in.
  3. Enter your registered email address in the "Email" field.
  4. Enter your password in the "Password" field.
  5. Click the "Sign In" button.
  6. If credentials are correct, you are redirected to the Dashboard.

IMPORTANT NOTES
  - If you forget your password, contact your Admin to reset it.
  - The app uses Supabase authentication. Your session is stored securely.
  - You will remain logged in even after closing the browser (persistent session).
  - If you see "Invalid credentials", check your email and password carefully.

ROLES
  After login, the application shows only the pages and actions your role allows.
  See Section 22 for a full Role & Permissions reference.

SECTION 2 — DASHBOARD (HOME)
================================================================================

PURPOSE
  The Dashboard is your starting point. It shows key metrics, quick-access
  buttons, and a summary of today's activity.

WHAT YOU SEE
  - Total Beneficiaries registered in the system
  - Services provided today
  - Pending sync count (records waiting to be uploaded)
  - Upcoming scheduled services
  - Quick-action buttons for common tasks

STEPS TO USE
  1. After login, you land on the Dashboard automatically.
  2. Review the metric cards at the top for a quick overview.
  3. Use the quick-action buttons (e.g., "Add Beneficiary", "New Service Entry")
     to jump directly to the relevant page.
  4. If there are pending syncs, click "Sync Now" to push offline records.

TIPS
  - The Dashboard refreshes its data each time you visit.
  - When offline, metrics reflect local Dexie (IndexedDB) data.
  - The pending sync counter will show 0 once all records are uploaded.

SECTION 3 — CALENDAR
================================================================================

PURPOSE
  View all scheduled and availed service entries in a monthly/weekly calendar
  view to plan and track appointments.

STEPS
  1. Click "Calendar" in the left sidebar navigation.
  2. The calendar opens on the current month by default.
  3. Each colored dot or event block represents a service entry.
  4. Click on an event to view details (beneficiary, service code, provider).
  5. Use the "<" and ">" arrows to navigate between months.
  6. Use the "Week" / "Month" toggle (if available) to change the view.

COLOR CODES
  - Green  : AVAILED (service was delivered)
  - Blue   : SCHEDULED (service is planned, not yet delivered)
  - Red    : Sync Failed entries

TIPS
  - Scheduled entries that have passed their date should be updated to AVAILED
    via the Service Entry page.
  - The calendar only shows entries that are stored locally or synced from the
    server depending on your online/offline state.

SECTION 4 — TOKEN MANAGEMENT
================================================================================

PURPOSE
  Issue daily tokens to beneficiaries visiting the camp. Tokens are sequential
  numbers that track walk-in order.

STEPS TO ISSUE A TOKEN
  1. Click "Token" or "Token Management" in the sidebar.
  2. The page shows today's last issued token number.
  3. Click "Issue Next Token" to generate the next token number.
  4. The token is displayed on screen — note it down or print it for the
     beneficiary.
  5. Token numbers reset at the start of each day automatically.

STEPS TO VIEW TOKEN HISTORY
  1. On the Token page, scroll down to see today's issued tokens.
  2. Each row shows: Token No., Beneficiary Name (if linked), Time Issued.

NOTES
  - Token numbers are stored locally and synced to the server.
  - If offline, tokens are issued from local storage and will sync later.
  - Only Staff, Manager, and Admin roles can issue tokens.

SECTION 5 — ADD BENEFICIARY
================================================================================

PURPOSE
  Register a new beneficiary (patient) into the ROW system.

STEPS
  1. Click "Add Beneficiary" in the sidebar or from the Dashboard quick-action.
  2. Fill in the required fields (marked with *):
       - Name *
       - Age *
       - Gender *
       - Phone Number *
       - Village / Address
       - Documents (BPL / APL / AADHAR / UDID / Not Applicable)
       - Condition (Neuro Muscular, Neurological, Pulmonary, etc.)
       - Any other fields shown on the form
  3. Click "Save Beneficiary".

  6. You can click "Add Assessment" button on the success/confirmation screen
     to immediately start an assessment for this beneficiary.

IMPORTANT NOTES
  - Each beneficiary receives a unique File Number assigned by the server.
  - Offline registrations use a temporary offline token (OFF-XXXXX) until synced.
  - Duplicate registrations are prevented by the system (phone number / name
    matching may apply based on configuration).

SECTION 8 — ASSESSMENT ENTRY (3-STEP WORKFLOW)
================================================================================

PURPOSE
  Record a full clinical assessment for a beneficiary. The assessment is split
  into three steps: Initial Assessment, Clinical Assessment, and Core Service
  Details.

--------------------------------------------------------------------------------
STEP 1: INITIAL ASSESSMENT
--------------------------------------------------------------------------------

  1. Click "Assessment Entry" in the sidebar or "Add Assessment" from a profile.
  2. On Step 1, fill in:
       - Patient ID / Beneficiary (search by name or file number)
       - Date of Assessment
       - Chief Complaint (select from dropdown)
       - Condition Type (Neuro Muscular, Neurological, Pulmonary, Disability,
         Amputation, Post Operative, Early Intervention Assessment)
       - History of Present Illness (free text)
       - Relevant Medical History
       - Any other fields shown for the selected condition
  3. Click "Next" to proceed to Step 2.

  NOTE: Fields change based on the Condition selected.

--------------------------------------------------------------------------------
STEP 2: CLINICAL ASSESSMENT
--------------------------------------------------------------------------------

  1. Step 2 shows condition-specific clinical fields:
       - For Neuro/Musculoskeletal: ROM, Muscle Strength, Balance, Coordination
       - For Pulmonary: Cough type, Dyspnea scale, Pulmonary symptoms
       - For Disability: Disability type, FIM score
       - For Amputation: Amputation level, Residual limb status, Prosthesis stage
       - For Post-Operative: Surgery type, Weight bearing status, Mobility
       - For Early Intervention: All developmental domains (Head Control, Rolling,
         Sitting, Crawling, Standing, Walking, Hand Function, Communication,
         Social, Self-Care, Attention, Play, Intelligence)
  2. Fill in all relevant fields for the selected condition.
  3. Enter "Short Term Goals" and "Long Term Goals" (free text).
  4. Enter "Treatment Plan" (free text).
  5. In the "Core Service Details" panel (within Step 2):
       a. Select Status: SCHEDULED or AVAILED
       b. Search and select the Beneficiary
       c. Set Schedule Date, Start Date, End Date (required if AVAILED)
       d. Select Location Code (default: MCB)
       e. Select Follow-up Number (auto-detected from history)
       f. Enter Service Provider Code / Name
       g. Select Mode of Services (default: ROW)
       h. In the "Services Provided" panel:
          - Select a Service Code from the dropdown
          - Enter Minutes for that service
          - Click "Add Service" to add more services
          - Each row will be saved as a separate Service History entry
  6. Click "Save & Continue" to save the assessment and all service entries.

  NOTE: Service entries are saved to Service History automatically.
        If online, they sync immediately. If offline, they sync when internet
        is restored.

--------------------------------------------------------------------------------
STEP 3: CONFIRMATION / FOLLOW-UP
--------------------------------------------------------------------------------

  1. After saving, a confirmation screen shows success messages.
  2. You can navigate to:
       - Assessment History to view the saved record
       - Service History to verify service entries
       - Add another assessment for the same or different beneficiary

SECTION 10 — SERVICE ENTRY
================================================================================

PURPOSE
  Manually add a service entry for a beneficiary outside of the assessment
  workflow.

STEPS
  1. Click "Service Entry" in the sidebar.
  2. Fill in the form:
       a. Status: Select SCHEDULED or AVAILED
       b. Beneficiary: Search by name or file number and select
       c. Schedule Date: Date the service is planned
       d. Start Date: Date service began
       e. End Date: Required if Status is AVAILED
       f. Location Code: Select from dropdown (default MCB)
       g. Follow-up Number: Select Initial Visit or Follow Up 1-4
          (auto-detected from history when beneficiary is selected)
       h. Service Provider Code / Name: Enter the provider's name or code
       i. Mode of Services: Select from dropdown (default ROW)
       j. Services Provided panel:
          - Row 1 is added automatically
          - Select a Service Code from the dropdown
          - Enter Minutes for that service (e.g., 30)
          - Click "Add Service" to add more rows
          - Each row saves as a SEPARATE entry in Service History
          - Click the red X button to remove a row
  3. Click "Save Entry" (or equivalent save button).
  4. Success message confirms all entries were saved.
  5. If online, entries sync immediately. If offline, they sync later.

VALIDATION RULES
  - At least one service row must be filled (code + minutes > 0).
  - Duplicate service codes in the same form are not allowed.
  - End Date is mandatory when status is AVAILED.
  - Start Date cannot be before Schedule Date.
  - End Date cannot be before Start Date.

SECTION 12 — BULK IMPORT SERVICES
================================================================================

PURPOSE
  Import multiple service entries at once using an Excel template instead of
  entering them one by one.

STEPS
  1. Go to Service History page (Section 11).
  2. Click the "Import Services" button.
  3. The Import Services modal opens.

DOWNLOADING THE TEMPLATE
  4. Click "Download Template" to get the Excel import template.
  5. Open the downloaded file in Excel or Google Sheets.
  6. The template has:
       - Green columns: Required fields (must be filled)
       - Yellow columns: Optional fields
       - Row 2: Hints explaining each column
       - Row 3: A sample row showing the correct format
       - Reference sheet: Lists all valid service codes, locations, modes

FILLING THE TEMPLATE
  7. Start filling data from Row 4 onwards (below the sample row).
  8. Required columns:
       - file_number: Beneficiary's file number (e.g., ROW-0001)
       - schedule_date: Date in YYYY-MM-DD format (e.g., 2026-06-15)
       - start_date: Date in YYYY-MM-DD format
       - service_code: Valid service code from the Reference sheet
       - total_minutes: Number of minutes (e.g., 30)
       - service_provider_code: Provider name or code
  9. Optional columns:
       - end_date, status, location_code, mode_of_service, custom_field2
 10. Save the file.

UPLOADING THE FILE
 11. Back in the Import modal, click "Upload File" or drag and drop your
     filled Excel file.
 12. The system validates each row.
 13. A summary shows: Rows processed, Imported successfully, Errors.
 14. If there are errors, click "Download Error Report" to get an Excel file
     listing which rows failed and why.
 15. Fix the errors in your original file and re-upload if needed.

NOTES
  - Duplicate entries (same file_number + service_code + date) are skipped.
  - Successfully imported entries sync to the server immediately if online.

SECTION 18 — SYNC CONTROL
================================================================================

PURPOSE
  Manually trigger synchronisation between local (offline) storage and the
  server (Supabase). Also used to pull beneficiary data from the server to
  your device.

STEPS — PUSH (Upload pending records)
  1. Click "Sync" or "Sync Control" in the sidebar.
  2. The page shows counts of pending records by type:
       - Beneficiaries pending sync
       - Service entries pending sync
       - Assessments pending sync
  3. Click "Sync Now" to push all pending records to the server.
  4. A progress indicator shows while sync runs.
  5. After completion, counts should drop to 0 for successfully synced items.
  6. "Sync Failed" items remain — check the error and fix before retrying.

STEPS — PULL (Download beneficiaries from server)
  1. On the Sync Control page, find the "Pull Beneficiaries" section.
  2. Optionally set a Date Range to pull only specific registrations.
  3. Click "Pull from Server".
  4. A progress bar shows downloaded count vs. total.
  5. New beneficiaries from other devices are now available locally.

WHEN TO USE SYNC CONTROL
  - After working offline for an extended period.
  - Before attending a camp in an area with no internet (pull data first).
  - When "Pending Sync" counts appear on the Dashboard.
  - When Service History shows "Sync Failed" entries.

AUTOMATIC SYNC
  - The app automatically syncs when you come back online.
  - Sync also runs after each Save action if you are online.

SECTION 21 — OFFLINE MODE GUIDE
================================================================================

PURPOSE
  Understand how the ROW application works when there is no internet connection.

WHAT WORKS OFFLINE
  - Adding new beneficiaries
  - Viewing beneficiaries already downloaded to your device
  - Creating service entries
  - Creating assessments (Initial, Clinical, Follow-up)
  - Issuing tokens
  - Viewing Service History (local records)
  - Viewing Assessment History (local records)

WHAT REQUIRES INTERNET
  - Pulling new beneficiaries from the server (other devices' registrations)
  - Viewing live bus tracking
  - Generating reports
  - Accessing the Admin Control Panel
  - Real-time sync (data pushes happen when online)

HOW OFFLINE STORAGE WORKS
  - All data entered offline is stored in your browser's IndexedDB (Dexie).
  - Records are tagged with sync_status = "pending".
  - When internet is restored, the app automatically pushes pending records.
  - Beneficiaries sync first (to get their file numbers), then service entries
    and assessments sync after.

SYNC STATUS GUIDE
  - "Pending Sync" (yellow badge): Record saved locally, not yet on server.
  - "Synced" (green badge)       : Record successfully saved on server.
  - "Sync Failed" (red badge)    : Upload failed. Hover to see the error.
                                   Go to Sync Control and click "Sync Now" to
                                   retry.

BEST PRACTICES FOR OFFLINE USE
  1. Before going to a camp with no internet: open the app while online so the
     latest beneficiary data downloads automatically.
  2. Use Sync Control → Pull Beneficiaries if you need records from the server
     that aren't on your device yet.
  3. After returning to an area with internet, wait for the auto-sync to
     complete (watch the pending count drop to 0 on the Dashboard).
  4. If auto-sync doesn't start, go to Sync Control and click "Sync Now".
  5. Check Service History after sync — verify no "Sync Failed" entries remain.
